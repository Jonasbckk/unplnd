UNPLND Design System

Version 1.0

Purpose

The design system guarantees that every screen in UNPLND feels like it belongs to the same product.
No screen should ever feel like it was designed by another person.
Every component follows the same rules.
Consistency is more important than creativity.

Design Philosophy

Inspired by
Apple

Screen Hierarchy

Every screen has:
1 Primary Action
1 Primary Focus
1 Clear Goal
If a screen has multiple competing actions...
simplify it.

Navigation

Bottom Navigation
Maximum:
5 Tabs
Navigation should always be obvious.
Never hide important actions.

Floating Action Button

Allowed only when it creates value.
Never use a FAB because it "looks modern."

Cards

Cards are the primary building block.
Cards must:
Have rounded corners.
Soft shadows.

                                                                         4
Comfortable padding.
Clear hierarchy.
Subtle animations.
Cards should feel touchable.

Lists

Avoid endless lists.
Prefer sections.
Group related information.
Use generous spacing.

Inputs

Large.
Comfortable.
Readable.
Never tiny.
Never difficult to tap.

Buttons

Buttons should feel satisfying.
Large tap targets.
Rounded.
Soft shadows.
Strong hierarchy.
Every screen has one Primary Button.

                                                                         5
Never create two equally important buttons.

Icons

Simple.
Outlined.
Consistent stroke width.
Never mix icon styles.
Never use emoji as icons.

Images

Large.
Immersive.
Natural.
Rounded.
Never use tiny thumbnails where a larger image improves emotion.

Empty States

Every empty state should:
Explain.
Encourage.
Inspire.
Never simply say:
"No Data."
Instead:
Let's create your first evening.

                                                                         6
Your memories will appear here.
Ready for tonight?

Loading States

Always use Skeleton Loading.
Never blank screens.
Never loading spinners alone.
The interface should feel alive.

Error States

Friendly language.
Simple explanation.
Retry button.
Never expose technical errors.

Accessibility

Minimum touch area:
44x44 px
Readable fonts.
Good contrast.
Support Dynamic Type.
Support VoiceOver.
Respect Reduced Motion.
Accessibility is mandatory.

                                                                         7
Haptics

Selection
Light Impact
Success
Error
Confirmation
Never overuse.
Every vibration should have meaning.

Consistency Rules

If a component already exists...
Reuse it.
Never create duplicates.
Never slightly redesign existing components.

Performance

UI must remain smooth.
60 FPS minimum.
Avoid unnecessary re-renders.
Optimize every animation.

Premium Rule

Every screen should feel like someone obsessed over every pixel.
If a detail feels average...

                                                                         8
Improve it.

Golden Rule

Users should never notice the design.
They should only notice how effortless everything feels.
That is excellent design.

Claude Instructions

Never invent new UI patterns.
Reuse existing components.
Follow spacing rules.
Follow radius rules.
Follow hierarchy.
Never compromise consistency.
The Design System has priority over personal preference.
